idevice-rs

Overview — WASM, TLS, Linux

All actions run in WASM + WebUSB. Pairing supplies HostID / SystemBUID for cleartext StartSession. When the device returns EnableSessionSSL, this build runs lockdown TLS (rustls) if you loaded a full XML pair-record plist that includes the PEM fields (HostPrivateKey, HostCertificate, RootCertificate, RootPrivateKey) — same idea as the native idevice crate. Use TLS client cert below: host matches pymobiledevice3; try root for libimobiledevice-shaped records. Verbose logs mux / pseudo-TCP to the console (and TLS-related steps as [wasm-tls]).

Linux + WebUSB: if selectConfiguration / claim fails while a native stack still talks to the phone, the host may be using usbmuxd while Chromium needs exclusive USB access — stop usbmuxd briefly (see errors below) and retry, or use a native client.

USB — mux vs QueryType

Mux vs QueryType — full text (technical)

After Request Apple device, both actions configure the Apple bulk interface, run the USB mux protocol (VERSION, optional SETUP on mux v2), then open a pseudo-TCP stream to lockdownd on port 62078 — same framing as idevice mux on the CLI, but in the browser.

Mux handshake stops once that tunnel is up: it does not send a lockdown plist. Use it to confirm WebUSB + mux + TCP to lockdownd work (output shows mux version + “cleartext path ready”).

QueryType does the same USB/mux/TCP setup, then sends lockdownd’s first cleartext request (QueryType) and shows the returned XML. That proves lockdownd responds before you use pairing / StartSession / battery below.

Info (lockdown + optional TLS)

If TLS fails or the device rejects the client cert, try another mode.

Fetch with plist — what it does

Load a full XML pair-record plist (including PEM keys), then Fetch with plist runs QueryType → StartSession → rustls (if needed) → GetValue. Battery/Diagnostics pass the same loaded plist text for TLS when SSL is required.

Returns an array of { name, data } (Uint8Array per file). Cap ~32 MiB total.
